<objective>
Wire the unified, CI-oriented harness entry point `scripts/verify-harness.ps1` that runs the
matrix-linked Maven test slice on JDK 25, emits the machine-readable coverage summary
`target/test-matrix-summary.json`, and optionally runs the Playwright console smoke. Extend the
Playwright suite so template-edit and job-trigger paths are covered and tied to documented matrix
rows. Add the PR/push CI workflow and contributor documentation. This satisfies TEST-03 (single CI
entry script), TEST-04 (machine-readable coverage summary), and TEST-06 (Playwright smoke wired to
matrix rows). It consumes the matrix from plan 01-01 and the example test classes + reusable YAML
fixtures from plan 01-02.
</objective>

<execution_context>
**Runtime:** Windows + PowerShell; CI on `ubuntu-latest` with `pwsh`. Maven via
`scripts/lib/repo-maven.ps1` `Invoke-RepoMaven` (JDK 25 + `.mvn/settings-jdk25.xml`).
**Default harness run = embedded fast path (D-10):** run only the Maven classes named in matrix
`linked_tests`, generate the summary, and SKIP Podman/Ollama/Docker. E2E is opt-in via `-IncludeE2e`
(D-11); E2E runtime is dual-mode `-UsePodman` (default, reuses `scripts/e2e-podman.ps1`) or
`-UseLocalService` (D-12).
**Exit semantics (D-13):** exit 1 only when a linked test fails; `pending` matrix rows never fail the
harness (P0 gating deferred to Phase 5 / COV-04).
**linked_tests formats:** Maven = simple class name, e.g. `ChunkedPipelineTests` (D-22); Playwright =
`e2e/specs/<file>.spec.ts#<test title>` (D-23). Module for a Maven class is inferred via matrix
`owner_module` metadata or convention (Claude's discretion per CONTEXT).
**Playwright config:** `data-generator-console-web/playwright.config.ts`, `fullyParallel: false`,
`workers: 1`, base URL `http://127.0.0.1:9876/console`. Helpers in `e2e/helpers/api.ts` expose the
`R<T>` envelope (`expectApiSuccess`, `unwrapApiData`, `fetchJobs`).
**CI:** follow `console-verify.yml` JDK 25 + Node 22 setup (do NOT change distributionManagement,
`.mvn` settings, or BOM versions — AGENTS.md ask-first boundary).
</execution_context>

<context>
There is no harness entry script today; `scripts/verify-console.ps1` and the `verify-ai-p*.ps1` family
are feature-pack slices the harness orchestrates via matrix `linked_tests` (CONTEXT code insights).
`Invoke-RepoMaven` returns the Maven exit code. Surefire writes XML reports to each module's
`target/surefire-reports/`; the summary builder parses those to decide row status (D-21). The
existing Playwright spec `template-workflow.spec.ts` already exercises save-template (matches the
`console-ui-template-edit` row reserved in plan 01-01); the job-trigger path needs a new spec mapping
to `console-ui-job-trigger`. `api.console.spec.ts` already has `GET /api/jobs` smoke via
`fetchJobs(request)`.

Locked decisions for this plan: **D-09** (create `scripts/verify-harness.ps1` unified entry,
orchestrates existing verify scripts via matrix), **D-10** (default embedded fast path; skip
Podman/Ollama/Docker), **D-11** (`-IncludeE2e` opt-in Playwright), **D-12** (dual-mode `-UsePodman` /
`-UseLocalService`), **D-13** (no fail on pending; exit 1 only on linked-test failure), **D-20**
(`target/test-matrix-summary.json` schema: `generatedAt`, `gitCommit` optional, `totals{covered,
partial, pending, skipped}`, `rows[{id, status, linkedResults[]}]`), **D-21** (result-driven status:
all linked green → covered; some green → partial; none/all fail → pending; conditional skips →
skipped-conditional), **D-22** (Maven linked_tests = simple class name; harness infers module),
**D-23** (Playwright linked_tests = `e2e/specs/<file>.spec.ts#<title>`), **D-24** (extend
`template-workflow.spec.ts` for template edit and add job-trigger spec; map to
`console-ui-template-edit` / `console-ui-job-trigger`), **D-25** (`.github/workflows/harness-verify.yml`
fast path on PR + main push), **D-26** (Playwright/Podman E2E as separate nightly job, not per-PR),
**D-27** (`docs/test-harness.md` full how-to + short `AGENTS.md` entry).

Deferred (do NOT implement): P0 merge gate / fail-on-pending, JaCoCo, exhaustive matrix, full-repo
`mvn test` as default.
</context>

<threat_model>
STRIDE register (ASVS L1; security_enforcement enabled). This plan adds a CI entry point, a workflow,
and console smoke tests — the surfaces are the CI runner, the coverage summary, and the job-trigger
path.

| STRIDE | Threat | Mitigation in this plan | Severity |
|--------|--------|-------------------------|----------|
| Spoofing | A matrix row's `linked_tests` names a non-existent class, so the summary reports `covered` without a real test running | Status is derived only from actual Surefire `<testcase>` results (D-21); a class with no executed result cannot resolve to `covered`. `failIfNoSpecifiedTests=false` is paired with result parsing, not blind success. | Medium |
| Tampering | `target/test-matrix-summary.json` is hand-edited to fake green coverage | Summary is regenerated on every harness run and re-emitted as a CI artifact; reviewers compare against the committed matrix. | Low |
| Repudiation | No record of which commit produced a coverage summary | Summary embeds `gitCommit` (`git rev-parse HEAD`) when git is available (D-20). | Info |
| Information disclosure | CI workflow logs leak Nexus credentials or the harness prints secrets | Harness uses `.mvn/settings-jdk25.xml` via `Invoke-RepoMaven` (no inline credentials); workflow adds no secret env vars; fast path runs only H2-backed embedded tests with no production datasources. | Medium |
| Denial of service | Default harness pulls Podman/Ollama/Docker or full-repo `mvn test`, making every PR slow/flaky | Default is the embedded fast path running only matrix `linked_tests` (D-10); E2E/Podman are opt-in (`-IncludeE2e`) and CI keeps them nightly/separate (D-26). | Medium |
| Elevation of privilege | The job-trigger smoke test runs an arbitrary template against real infrastructure | Job-trigger spec uses the in-memory H2 `writer-jdbc-basic` fixture scenario (D-19) against the Podman/local test service only — no production endpoints. | Medium |

**Blocking severities (high) addressed:** none at high severity. Coverage-spoofing (medium) is
mitigated by result-driven status; credential disclosure (medium) by reusing the repo Maven settings
and adding no secrets to the workflow.
</threat_model>
