# Phase 1: Test Harness Foundation - Context

**Gathered:** 2026-06-17
**Status:** Ready for planning

<domain>
## Phase Boundary

Deliver a documented, runnable test harness for the data-generator platform: a feature matrix mapping platform capabilities to tests, a reusable synthetic-data fixture library, a single CI-oriented entry script (`verify-harness.ps1`), machine-readable coverage summaries, and Playwright smoke paths tied to matrix rows. This phase establishes the foundation; P0 merge gates and exhaustive matrix completion belong in Phase 5.

**Requirements in scope:** TEST-01 through TEST-06

</domain>

<decisions>
## Implementation Decisions

### Feature Matrix Shape & Format
- **D-01:** Rows are organized **capability-first** — primary dimensions are reader / writer / transform / console; columns include `id`, `capability`, `adapter`, `test_types[]`, `owner_module`, `status`, `linked_tests[]`, `notes`.
- **D-02:** **YAML is the source of truth** at `.planning/test-matrix.yaml`. Human-readable docs are generated from YAML, not maintained separately.
- **D-03:** Phase 1 uses **coarse granularity** (~30–50 rows): one row per adapter class plus 5–10 core console flows. Fine-grained per-test-class rows are out of scope for Phase 1.
- **D-04:** **Owner** is the owning **Maven module** (e.g. `data-generator-calcite`, `data-generator-service`).
- **D-05:** **Status** enum: `covered` | `partial` | `pending` | `skipped-conditional` (for Ollama/Docker `@EnabledIf` / `Assumptions` skips).
- **D-06:** Console matrix rows split **API and UI**: e.g. `console-api-templates`, `console-ui-template-edit`, `console-ui-job-trigger` as separate rows.
- **D-07:** Initial matrix catalog is **semi-automatic**: `scripts/generate-test-matrix-draft.ps1` reads `.planning/codebase/STRUCTURE.md` and `TESTING.md` to emit a draft YAML; a human reviews and commits the final matrix.
- **D-08:** `docs/test-feature-matrix.md` is **generated by script** from `.planning/test-matrix.yaml` (run as part of harness or a dedicated step).

### Harness Entry Script
- **D-09:** Create **`scripts/verify-harness.ps1`** as the unified CI-oriented entry point (TEST-03). It orchestrates existing `verify-*.ps1` scripts where matrix rows reference them.
- **D-10:** **Default run = embedded fast path**: Maven tests for matrix `linked_tests` only; generate coverage summary; **skip** Podman, Ollama, and Docker-dependent tests unless explicitly requested.
- **D-11:** **`-IncludeE2e`** flag explicitly enables Playwright smoke (not run by default).
- **D-12:** E2E runtime supports **dual mode**: `-UsePodman` (default, reuses `scripts/e2e-podman.ps1`) or `-UseLocalService` for local Spring Boot.
- **D-13:** Phase 1 harness **does not fail on `pending` matrix rows**; exit code 1 only when linked tests fail. P0 blocking gates deferred to Phase 5 (COV-04).

### Synthetic Fixture Library
- **D-14:** Add top-level Maven module **`data-generator-test-fixtures`** (sibling to `data-generator-calcite` in root `pom.xml`), packaged as **test-jar** for test-scope-only consumption.
- **D-15:** Fixtures combine **YAML Template V2 templates** with **minimal static Java helpers**: `FixtureTemplates.load("reader-jdbc-basic")`, `H2Seed.apply(sql)`.
- **D-16:** Seed data supports **both** inline H2 SQL scripts (`fixtures/sql/*.sql`) **and** CSV/JSON files for file-reader paths.
- **D-17:** Files named by **scenario** (e.g. `fixtures/templates/reader-jdbc-basic.yaml`, `writer-kafka-smoke.yaml`), not necessarily 1:1 with matrix row IDs.
- **D-18:** Provide **one embedded example per adapter class** aligned with coarse matrix rows (reader, writer, transform each covered; TEST-05).
- **D-19:** **Playwright reuses the same YAML fixtures** — E2E uploads templates via API rather than maintaining separate E2E-only fixture files.

### Coverage Summary Contract (TEST-04)
- **D-20:** Primary output: **`target/test-matrix-summary.json`** with schema: `generatedAt`, `gitCommit` (optional), `totals{covered, partial, pending, skipped}`, `rows[{id, status, linkedResults[]}]`.
- **D-21:** Status is **test-result-driven**: all `linked_tests` green → `covered`; some green → `partial`; none or all fail → `pending`; conditional skips → `skipped-conditional`.
- **D-22:** **`linked_tests` format — Maven:** simple class name (e.g. `ChunkedPipelineTests`); harness infers module via matrix metadata or convention.
- **D-23:** **`linked_tests` format — Playwright:** `e2e/specs/<file>.spec.ts#<test title>` (e.g. `template-workflow.spec.ts#save template`).
- **D-24:** Extend existing specs for TEST-06: **`template-workflow.spec.ts`** (template edit) and **`api.console.spec.ts`** or equivalent (job trigger); map to `console-ui-template-edit` and `console-ui-job-trigger` matrix rows.

### CI & Contributor Documentation
- **D-25:** Add **`.github/workflows/harness-verify.yml`** invoking `verify-harness.ps1` fast path on **PR and main push**.
- **D-26:** Playwright/Podman E2E runs as a **separate nightly job** (extend or parallel `console-verify.yml`); not required on every PR.
- **D-27:** Contributor docs: **`docs/test-harness.md`** (full how-to: quick start, flags, matrix maintenance, fixture authoring, JSON summary interpretation) plus a short entry in **`AGENTS.md`**.

### Claude's Discretion
- Exact draft-generation heuristics in `generate-test-matrix-draft.ps1` (which adapters to include in first ~30–50 rows).
- Module inference logic when resolving simple Maven class names to `-pl` targets.
- Whether `harness-verify.yml` uses the same JDK 25 setup as existing workflows (follow `console-verify.yml` patterns).

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **`EmbeddedKafkaTestSupport`**, **`EmbeddedElasticsearchHttpSupport`**, **`DockerTestSupport`** — Reference-counted embedded infra; fixture examples should reuse these patterns.
- **`ChunkedPipelineTests`**, **`TemplateV2RunnerKafkaEmbeddedTests`** — Template for reader/writer/transform embedded pipeline tests; fixture module should extract reusable YAML/SQL from these patterns.
- **`scripts/verify-ai-p1.ps1` … `verify-ai-p10.ps1`**, **`verify-execution-reliability.ps1`** — Feature-pack slices to orchestrate from harness via matrix `linked_tests`.
- **`V2ScenarioTemplateIT`** — Service-level scenario integration pattern for template runs.

### Established Patterns
- **Embedded-first**: H2 with `MODE=PostgreSQL`; skip (not fail) when Docker/Ollama absent.
- **Verify scripts**: PowerShell + `Invoke-RepoMaven` + explicit `-Dtest` class lists + optional Playwright via `-SkipPlaywright`.
- **No JaCoCo**: coverage is matrix-row-based, not line coverage — do not add JaCoCo in Phase 1 without explicit decision.
- **Console E2E**: `fullyParallel: false`, `workers: 1`; Podman on port 9876 default.

### Integration Points
- Root `pom.xml` — add `data-generator-test-fixtures` module; calcite and service add test-scoped dependency.
- `.planning/test-matrix.yaml` — new file; consumed by harness script and doc generator.
- `.github/workflows/` — new `harness-verify.yml`; nightly E2E parallels `console-verify.yml`.
- `docs/` — new `test-harness.md` and generated `test-feature-matrix.md`.

</code_context>
