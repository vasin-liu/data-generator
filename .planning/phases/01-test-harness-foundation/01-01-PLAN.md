<objective>
Define the feature-matrix schema and produce the initial coarse row catalog for the data-generator
platform. The matrix at `.planning/test-matrix.yaml` becomes the single source of truth that maps
platform capabilities (readers, writers, transforms, console flows) to test types, owning Maven
modules, and the test classes/specs that cover them. A semi-automatic draft generator seeds the
catalog from existing codebase maps; a separate renderer produces the human-readable
`docs/test-feature-matrix.md`. This plan satisfies TEST-01 and supplies the row IDs and
`linked_tests` contract that plans 01-02 (fixtures) and 01-03 (harness/summary) depend on.
</objective>

<execution_context>
**Runtime:** Windows + PowerShell. Scripts run under `pwsh`/`powershell`. No Maven or Java execution
is required by this plan — it produces data files and PowerShell generators only.
**Working dir:** repository root `D:\Work\99_Code\01_Java\data-generator`.
**No module/POM changes** in this plan. Root `pom.xml` is owned by plan 01-02 (do not touch it here).
**Conventions:** YAML keys, file paths, and identifiers stay English. The generated markdown doc may
include bilingual headings but row data stays English.
</execution_context>

<threat_model>
STRIDE register (ASVS L1; security_enforcement enabled). This plan produces planning data and
PowerShell generators — no network, no auth surface.

| STRIDE | Threat | Mitigation in this plan | Severity |
|--------|--------|-------------------------|----------|
| Spoofing | A matrix row claims coverage by naming a test class that does not exist, faking green status | `linked_tests` only filled for classes/specs verified to exist in TESTING.md; unverified rows stay `pending`. Plan 01-03's summary is test-result-driven, so a non-existent linked test cannot resolve to `covered`. | Low |
| Tampering | Hand-edits to `docs/test-feature-matrix.md` drift from the YAML source of truth | Doc carries a "generated — do not edit" banner and is regenerated deterministically (D-08); YAML is the only source of truth (D-02). | Low |
| Repudiation | No record of how the catalog was seeded | Draft generator documents its STRUCTURE.md/TESTING.md inputs; human review step before commit (D-07). | Info |
| Information disclosure | Matrix or doc leaks credentials/hostnames | Matrix stores only capability metadata and test identifiers — no secrets, URLs, or credentials are permitted in any column. | Low |
| Denial of service | Draft generator overwrites the curated matrix, destroying review work | Draft writes to a separate `.planning/test-matrix.draft.yaml` and refuses to clobber an existing file without `-Force`. | Medium |
| Elevation of privilege | n/a — scripts perform only local file IO, no elevation | Scripts invoke no external binaries beyond PowerShell file cmdlets. | Info |

**Blocking severities (high) addressed:** none at high severity; the DoS (accidental overwrite of
curated matrix) is mitigated by the draft/source-of-truth separation and `-Force` guard.
</threat_model>
