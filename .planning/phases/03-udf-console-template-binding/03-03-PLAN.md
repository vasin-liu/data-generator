<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator browser → console SPA | User-entered upload form data (udfId/version/type + file or script/sql text) crosses into the SPA before being POSTed to `/api/console/udfs` |
| SPA → `/api/console/udfs` | Client requests carry the `X-Console-Role` header; the backend filter (03-02) enforces RBAC when security is enabled |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03-01 | Elevation of privilege | UDF mutation calls from SPA | transfer | Authorization is enforced server-side by `ConsoleAuthorizationFilter` (03-02, D-15); the SPA only attaches `X-Console-Role` via existing `consoleRoleHeaders()` — the client is not the trust anchor |
| T-03-03-02 | Tampering / XSS | rendering UDF metadata + script/sql text in the table | mitigate | Render values as React text/AntD components (auto-escaped); do not use `dangerouslySetInnerHTML` for any UDF-sourced field (script body, sqlName, metadata) |
| T-03-03-03 | Information disclosure | list/version views in the UI | mitigate | The page consumes `UdfGroupView`/`UdfVersionView` which exclude payload bytes (03-02 DTOs); no payload is fetched or rendered |
| T-03-03-04 | Tampering | i18n key drift between locales | mitigate | Enforce en/zh-CN key parity for all `udfs.*` keys (Task 3 acceptance) so no untranslated/raw key leaks to operators |
| T-03-03-SC | Tampering | npm dependency installs | accept | No new npm dependencies are added — reuses existing AntD 5, React Query, react-i18next, React Router 7; slopcheck N/A |
</threat_model>
