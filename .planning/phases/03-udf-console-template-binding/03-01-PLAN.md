<objective>
Introduce JDBC persistence behind the Phase 2 `UdfRegistry` so uploaded/published UDFs survive restart, and rehydrate published UDFs into the Template V2 runtime merge view on startup — all without changing the Phase 2 `UdfRegistry`/`UdfRecord` contract.

Purpose: Phase 3 console upload (UDF-05) requires durable artifact storage (D-01) and cross-restart availability (D-02). Phase 2 left the registry in-memory; this plan adds the persistence layer additively (D-04).
Output: `UdfArtifactPO`, `UdfArtifactRepository`, `JdbcUdfRegistry`, `UdfStartupReloader`, and a `CoreConfig` bean override that activates the JDBC-backed registry.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UDF payload bytes → JDBC store | Code-bearing artifact bytes (JAR/script/sql) cross from upload into durable storage; they are persisted but not executed in this plan |
| JDBC store → runtime registry (startup) | Persisted `PUBLISHED` rows re-enter the Template V2 runtime merge view on `ApplicationReadyEvent` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01-01 | Tampering | `JdbcUdfRegistry.publish/registerDraft` | mitigate | Reuse Phase 2 validation regexes (udfId reverse-DNS, strict semver) and the `UDF_DUPLICATE_VERSION` guard; published rows are immutable — `publish`/`deprecate` only transition state, never rewrite payload (D-08) |
| T-03-01-02 | Information disclosure | `UdfArtifactPO.payload` / logging | mitigate | Never log payload bytes; `UdfStartupReloader` logs only published-row counts, not contents; payload column is BLOB, not echoed in any toString |
| T-03-01-03 | Elevation of privilege | `UdfStartupReloader` re-entering runtime | accept | Only rows already in state `PUBLISHED` (which passed the Phase 2 publish gate, D-21) are rehydrated; the DB is the trusted store; no governance re-run on reload is required this phase |
| T-03-01-04 | Denial of service | large JAR `payload` BLOB | accept | Payload size limits / artifact scanning quotas are explicitly deferred (03-CONTEXT Deferred Ideas); H2/JDBC BLOB handles current sample-scale artifacts |
| T-03-01-SC | Tampering | maven/npm dependency installs | accept | No new package-manager dependencies are added in this plan (only existing managed Spring Data JPA / Lombok); slopcheck N/A |
</threat_model>
