<decisions>
## Implementation Decisions

### LINE_SAMPLE preview sample fields
- **D-01:** Extend `GeoSyntheticPreviewRequest` with a nested **`sample`** object mirroring `GeoSyntheticSampleVO` / YAML: `{ strategy, spacingMeters }` (not flat top-level fields).
- **D-02:** `GeoAssetService.toPreviewSource` MUST forward `sample.strategy` and `sample.spacingMeters` onto `GeoSyntheticSourceVO.setSample(...)` so `GeoSyntheticRequestMapper` / `GeoSyntheticGenerator` see the same LINE_SAMPLE config as a full-run draft (count still comes from preview `maxCount` honesty cap).
- **D-03:** Console editor (`GeoSyntheticSourceFields` → `previewSyntheticPoints`) MUST include `sample` on `POST …/preview/synthetic` when mode is `LINE_SAMPLE` (strategy + spacingMeters from form state). Also send already-supported fields that affect honesty when present in the form (`featureIndex`, `randomFeature`, `minDistanceMeters`) — no new UI controls required beyond wiring what the form already edits.
- **D-04:** When mode is `LINE_SAMPLE` and `sample` / `strategy` is omitted on the preview request, **default `strategy` to `BY_COUNT`** (same as editor form default) rather than inventing a separate preview-only error — runtime full-run validation remains unchanged for saved templates.
- **D-05:** Add/extend focused tests (`GeoAssetServiceTests` and/or `ConsoleGeoAssetPreviewIT`) proving LINE_SAMPLE + `BY_COUNT` and `BY_SPACING_METERS` reach generation (preview succeeds / sample strategy applied). Keep bar Maven unit/IT — no Playwright requirement for 23.1.

### Dual-binding docs (preview vs runtime)
- **D-06:** **Docs-only clarification** — do **not** change runtime `GeoSyntheticRequestMapper` fail-fast when both path and asset-id are set for the same role; do **not** change editor “asset-id wins” preference (Phase 22 D-16 / client clears path when asset-id set for preview calls).
- **D-07:** In `docs/geo-synthetic-v2-source.md` and/or `docs/geo-assets.md`, add an explicit **two-path** note:
  - **Editor / preview:** when both bindings appear in the form, **asset-id is preferred** for preview calls (path cleared client-side); inline warning remains UX.
  - **Runtime execute:** mapper **fail-fasts** if both path and asset-id are present on the saved source — operators must leave one binding only in YAML/draft before run.
- **D-08:** Prefer short cross-links between the two docs over duplicating long prose; wording must be unambiguous enough that “asset-id wins” is not misread as runtime silent preference.

### Exact preview API paths
- **D-09:** `docs/geo-assets.md` Related API table MUST name exact locked paths (no “or equivalent”):
  - `POST /api/console/geo-assets/preview/location`
  - `POST /api/console/geo-assets/preview/synthetic`
- **D-10:** Brief note that synthetic preview body mirrors `geo_synthetic` fields including nested `sample` for LINE_SAMPLE; do not invent a full OpenAPI chapter — point at controller/DTO if detail needed.

### Scope freeze
- **D-11:** Intentionally deferred audit items stay out: GEO-06, DATA-01, P0 inflation, optional Playwright→P1, Spring metadata-DB upload→run IT, Nyquist VALIDATION.md for 21–23.

### Claude's Discretion
- Exact Java nested type shape (`record Sample(...)` vs reuse VO) as long as JSON field names match YAML (`sample.strategy`, `sample.spacingMeters`)
- Whether dual-binding clarification lives primarily in geo-assets vs geo-synthetic-v2-source (both must be consistent)
- Test class split (service unit vs controller IT) as long as D-05 evidence exists
- Plan packing (one vs two plans) — prefer minimal plan count for this small cleanup
