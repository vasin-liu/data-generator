  <action>
    Extend `SinkWriteMetric` with `rowsRead`, `rowsUpserted`, `rowsSkipped` counters.
    **Explicit `SinkWriteExecutor` metric wiring (D-16, W-03):**
    - `rowsRead`: increment in `SinkWriteExecutor` (or delegated source-read hook) by rows accepted into each sink write batch — for streaming/chunked runs this is rows passed to the sink stage for that writer, not global source total unless single-sink template
    - `rowsWritten` / `rowsOk`: existing successful write counter (unchanged semantics)
    - `rowsUpserted`: populated by `JdbcBulkWriteExecutor` upsert path (08-05); `SinkWriteExecutor` merges executor metrics into per-sink `SinkWriteMetric`
    - `rowsSkipped`: increment when a row is intentionally not written (validation filter, null-key skip, duplicate skip before JDBC) — document skip reasons in Javadoc; do not conflate with `rowsFailed`
    Extend `StageMetricVO` record with optional `Long rowsRead`, `Long rowsUpserted`, `Long rowsSkipped` — use compact constructor null-to-zero normalization mirroring `RunReportVO` pattern.
    Ensure `RunReportVO` serializes new sink fields without breaking existing JSON consumers (additive fields only).
    Update `RunMetrics.addRead` / sink recording to populate rowsRead per source/sink stage where applicable.
  </action>
  <acceptance_criteria>
