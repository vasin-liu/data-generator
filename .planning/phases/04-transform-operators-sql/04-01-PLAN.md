<objective>
**Purpose:** Add the three new built-in Template V2 transform operator configuration VOs — `json`, `mask`, `lookup` — as additive polymorphic `TransformVO` subtypes (XFORM-02 model layer). This is the foundation wave: every downstream plan (factories, catalog, error surfacing, harness) references these exact type strings and field shapes.

**Output:** Four new VO classes in `data-generator-common/data-generator-core` model/v2 (`JsonTransformVO`, `MaskTransformVO`, `MaskRuleVO`, `LookupTransformVO`) plus one subtype round-trip test. New `type` values are purely additive to the Template V2 schema (per D-13): existing `sql`/`spel`/`js` templates keep parsing unchanged. Operator field choices (D-02 json parse + opt-in flatten, D-03 mask named strategies, D-04 lookup against an in-template named source) are realized as the VO field set here; runtime behavior lands in 04-02.
</objective>

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-04-01-01 | Tampering | `type` discriminator binding | mitigate | Only `@JsonSubType`-registered subtypes resolve; an unknown `type` fails Jackson binding rather than instantiating arbitrary classes (closed polymorphism via JsonSubtypeRegistry, no default typing). |
| T-04-01-02 | Denial of Service | `separator`/`flatten` config in JsonTransformVO | accept (defer runtime guard to 04-02) | VO holds config only; deep-JSON/large-string parse bounds are enforced in `JsonTransformFactory` (T-04-02 register). VO sets safe default `separator = "."` and `flatten = false`. |
| T-04-01-03 | Information Disclosure | MaskRuleVO strategy values | mitigate | `strategy` is a closed name set (email/phone/credit-card/generic-fixed) validated at apply-time in 04-02; VO Javadoc documents the allowed set so authors cannot expect custom regex here (custom masking → audited Phase 3 UDF path). |
| T-04-01-04 | Tampering | additive schema change | mitigate | No edit to `TransformVO` base or existing subtypes; Task 4 asserts legacy `sql` still binds (D-13), preventing accidental breaking schema drift. |
</threat_model>
