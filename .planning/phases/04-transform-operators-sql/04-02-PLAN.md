<objective>
**Purpose:** Implement runtime behavior for the three operators from 04-01 (XFORM-02) and add the XFORM-03 SQL-surface enhancement. Ship exactly three new built-in operators — `json`, `mask`, `lookup` (D-01) — as `V2TransformFactory` implementations, register them in the default runtime plugin, and add ONE internal Calcite scalar function `V2_JSON_EXTRACT(json, path)` as the XFORM-03 SQL-surface enhancement: a namespace-safe scalar usable directly from `sql` transforms (D-11), kept internal/uncataloged with a `V2_` prefix so it avoids the UDF `sqlName` namespace (D-12). It is INDEPENDENT of the `json` operator — that operator parses in pure Java and `V2_JSON_EXTRACT` does NOT internally back it; the function simply extends what an author can express inside a `sql` transform.

**Output:** Three new factory classes in `org.gensokyo.data.calcite.transform`, one new internal SQL-function helper `TemplateV2JsonSqlFunctions` registered through `TemplateV2SqlFunctionRegistry.builtIn()`, updated `DefaultTemplateV2RuntimePlugin` (factories + `transform(...)` capabilities), and four embedded unit tests. Operators mirror `SpelTransformFactory` (read table `input`, merge schema, return `TransformResult`). Failures throw `IllegalArgumentException`/`IllegalStateException` carrying the offending column/key so the runtime's `runtimeFailure(...)` wrapper produces a locatable message (seed of D-08, fully surfaced in 04-04).
</objective>

<threat_model>
## Trust Boundaries
| Boundary | Description |
|---|---|
| TB-04-02-A | Untrusted template YAML config → operator execution (JSON string parse, mask of sensitive columns, lookup key joins) |
| TB-04-02-B | Row data flowing through factories → exception messages surfaced into run reports / job detail |
| TB-04-02-C | Internal `V2_JSON_EXTRACT` scalar function callable from `sql` transforms |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-04-02-01 | Denial of Service | JsonTransformFactory parse of attacker-sized/deeply-nested JSON | mitigate | Parse with the standard Jackson mapper (default depth limits apply); flatten recursion bounded by parsed structure; truncate any value snippet in error messages so a hostile payload cannot blow up the report. |
| T-04-02-02 | Information Disclosure | Mask operator must not leak full PII in errors/output | mitigate | MaskTransformFactory never echoes the raw cell value in exceptions (column + strategy only); masked output keeps only the documented non-sensitive remainder (e.g. last 4 digits). Test asserts no raw value in error text. |
| T-04-02-03 | Tampering | Unknown mask strategy / lookup miss | mitigate | Fail-fast `IllegalArgumentException`/`IllegalStateException` (D-10) terminates the run rather than silently masking nothing or fabricating joins. |
| T-04-02-04 | Elevation of Privilege / Namespace collision | V2_JSON_EXTRACT vs UDF sqlName namespace | mitigate | `V2_` prefix is reserved for built-in functions and is excluded from the UDF sqlName space (D-12); function is internal-only and never cataloged, so operators cannot shadow a published UDF by name. |
| T-04-02-05 | Denial of Service | Lookup index over a large named source | accept | Bounded by the in-template source row count (already materialized for the run); single-pass HashMap index is O(n) memory, consistent with existing multi-table SQL transforms; no external/unbounded datasource read (D-04). |
</threat_model>
